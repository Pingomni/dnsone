The console's time zone, chosen from the console.

## What changes

- **Settings → Overview → Time zone.** Choose the zone the console shows every time in, e.g. `Europe/Tirane`, and
  **Save**. The clock in the top bar, the audit log, the query log and the charts follow at once, for every
  operator and on every node of a cluster. Until now this meant editing `DNSONE_TIMEZONE` in
  `/etc/dnsone/dnsone.env` as root and restarting the console.
- It changes only how times are shown: the server's own clock and the stored data are not touched.
- Until a zone is chosen, the console keeps the one it has today (`DNSONE_TIMEZONE`, set when DNSOne was
  installed). Once one is chosen in the console, that one is used and `DNSONE_TIMEZONE` no longer matters.
- A change is recorded in the audit log, and the *Settings* section of a backup now carries the time zone.
- No database migration, and DNS keeps answering throughout the update.

## Installing

- A new server: `curl -fsSL https://raw.githubusercontent.com/Pingomni/dnsone/main/install.sh -o install.sh`, then
  `sudo bash install.sh`.
- A running server: *Settings → Software update* → **Install**, or `sudo dnsone-update`.
