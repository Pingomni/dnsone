DNSOne 1.4.4: a full check of the console's links and pages, smoother scrolling, and fixes to caching and security headers.

## Fixed

- **Security headers on the console page.** nginx dropped the server's security headers (Content-Security-Policy, HSTS, X-Frame-Options, ...) wherever a location set its own Cache-Control, so the console page and its scripts were served without them; only the API had them. They now come from one snippet, `/etc/nginx/snippets/dnsone-headers.conf`, included in every such location. Updating patches the site file in place (your certificate lines are kept), checks it with `nginx -t`, and leaves it unchanged if that fails.
- **Back and Forward** return to where the page was scrolled, instead of the top.
- **Switching tabs** (zones, settings, ad-blocking, ...) keeps the position instead of jumping to the top while the new tab loads.
- **Paging through a list** (First, Previous, Next, Last; Older in the query log) shows the top of the list, instead of the middle of the next page.
- **The phone menu** holds the page still behind it.
- Built files are sent with one Cache-Control header instead of two.

## New

- **Reload after an update.** A console left open while DNSOne is updated shows "DNSOne X is installed. Reload to use the new version of the console." The API reports its version on every answer (`X-DNSOne-Version`).
- **`ops/dnsone-postinstall`**, run by `dnsone-update` after every install, brings the system configuration in line with the release. It is safe to run again.

## Checked

Every page and tab, as an administrator, a reseller and a customer, at desktop and phone width: no broken links, no script errors, no failed requests, no sideways scrolling.

## Installing

Settings → Overview → Software update, or `sudo dnsone-update`. Updating from 1.4.3 or older: afterwards, run `sudo dnsone-update` once more so the older updater's missing step (the nginx headers) is applied; it says "Nothing to do" and fixes the configuration.
