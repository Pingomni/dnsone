Setting up a cluster from the console, and a fix for the installer.

## What changes

- **New (Pro): set up a cluster from the console, with no terminal.** On the primary, *Settings → Cluster →
  Add server* with the new server's address; in a few seconds it is ready and the page shows its **join key**.
  On the new server, *Settings → Cluster → Join a cluster* with that key. The new server then uses the
  primary's database and its BIND follows the primary's zones; changes made on either console reach both
  within 30 seconds. Behind it:
  - a MySQL account only the new server's address may use, over TLS only (checked against the primary's own
    certificate);
  - MySQL and BIND listening on the primary's address;
  - with ufw or the DNSOne firewall on, ports 3306 and 5301 opened to that server alone.
  *Leave the cluster* on a replica gives it back its own database and zones; *Remove* on the primary
  deletes the server's account. If a join fails, the server keeps its own configuration. Both servers need
  the same DNSOne version and a licence.
- **Fixed: the installer could stop at step 8 with "Duplicate entry 'node.…' for key 'settings.PRIMARY'".** Step 8
  starts the sync timer, which syncs at once, and then syncs itself; when both wrote the server's first heartbeat at
  the same moment, one failed and the installer stopped before nginx, the firewall and the verification. A heartbeat
  is now a single statement that creates or updates the record. Hit by it? Run `sudo bash install.sh` again: it
  keeps the secrets, the database and the administrator, and finishes.

## Upgrading from 1.5.5

`sudo dnsone-update` (or *Settings → Overview → Software update*): no database changes. The update installs
`dnsone-cluster.path`, which the console needs to set up a cluster.
